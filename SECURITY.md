# Безопасность и публикация

## Что должно оставаться локально

Не публикуйте `.env` и его копии, API-ключи и токены, приватные ключи кошельков, TOTP-секреты, прокси с паролями, состояние браузера, SSH/Cloudflare-файлы, историю shell, серверные дампы, торговые данные, скриншоты авторизованных страниц и необработанные логи.

В публичный репозиторий входит только `.env.example` с пустыми полями учётных данных. Рабочие файлы сохраняйте в `app/data/` либо вне репозитория. Произвольный путь из `MEXC_WEB_TOKEN_FILE` не становится безопасным автоматически: он тоже должен быть исключён из Git.

`.gitignore` не удаляет файлы с диска и не убирает ранее закоммиченные секреты. Он также не защищает архив, созданный рекурсивным копированием всей рабочей папки.

## Подготовка релиза

1. Выполните `python scripts/check_public_release.py` и проверьте состав через `git status --short`.
2. Просмотрите diff перед коммитом. Скрипт — дополнительная проверка, а не доказательство отсутствия всех возможных секретов.
3. Для передачи исходников используйте `python scripts/check_public_release.py --export`: он архивирует ровно проверенные файлы, без локальной Git-истории.
4. Перед изменением видимости существующего репозитория отдельно проверьте все ветки, теги, историю, release assets и логи CI. Для первого публичного релиза из частного серверного среза используйте новый репозиторий с проверенными исходниками.

## Если секрет уже попал в публикацию

Отзовите или замените затронутые токены и API-ключи у соответствующего провайдера. Затем очистите текущие файлы и историю, учтите форки, клоны, архивы и CI-артефакты. Удаление строки новым коммитом не делает старое значение недоступным. Для приватных ключей кошельков недостаточно удалить файл: такой ключ нельзя считать секретным после раскрытия.

## Сообщение об уязвимости

Не публикуйте действующие секреты в issue, PR, логах или комментариях. Если в публичном репозитории включён приватный канал сообщения об уязвимостях, используйте его. Если такого канала нет, в issue можно запросить способ приватной связи, не раскрывая секретов и деталей эксплуатации. Приложите обезличенные шаги воспроизведения и версию кода.
