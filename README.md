# CEX–CEX Spread Bot

Python-проект для поиска спредов между фьючерсными биржами и исполнения парных сделок. Содержит **два отдельных сервиса**: парсер рыночных данных и торговый бот, связанный с парсером через Redis Streams.

## Состав

- **Парсер** — сопоставляет инструменты между биржами, сравнивает котировки, подтверждает спреды, отправляет уведомления в Telegram и события открытия/закрытия в Redis.
- **Трейдер** — получает события из Redis, управляет двумя сторонами сделки, отслеживает исполнение и закрытие позиций, комиссии и P&L.
- **Dry-run клиент** — симулирует исполнение на публичных рыночных данных с виртуальным балансом.

```text
Котировки бирж → CEX–CEX парсер → Telegram
                        │
                   Redis Streams
                        │
                   CEX–CEX трейдер
                        │
               LONG на A / SHORT на B
```

## Биржи

В реестре рыночных данных подключены Bybit, OKX, Gate, Bitget, BloFin, KuCoin, HTX, BingX, Phemex, BitMart, CoinEx и LBank. Для этих 12 бирж присутствуют торговые адаптеры.

Также сохранён MEXC-адаптер трейдера и необходимые ему вспомогательные файлы. Источник MEXC в CEX–CEX парсере этого среза не подключён, поэтому он не включён в стандартные списки бирж примера конфигурации.

## Настройка

Исходный проект использует Python 3.11+ и Redis. Конфигурация задаётся переменными окружения и файлом `.env`.

```bash
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# Windows PowerShell: .\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Создайте `.env` по образцу [.env.example](.env.example) и укажите собственные Telegram-параметры и `REDIS_URL`. Биржевые ключи нужны для реальной торговли; для парсера и dry-run клиента они не требуются. Парсер и трейдер должны использовать один Redis и одинаковый `CEX_SPREAD_STREAM_KEY`.

Исходные точки входа, запускаемые отдельными процессами:

```bash
python -m app.cex_spread.main
python -m app.cex_spread_trader.main
```

## Настройки режимов

| Параметр | Назначение |
| --- | --- |
| `CEX_SPREAD_EXCHANGES` | Биржи парсера |
| `CEX_SPREAD_TRADER_EXCHANGES` | Биржи трейдера |
| `CEX_SPREAD_MIN_SPREAD_OPEN_PCT` | Порог открытия, в процентах |
| `CEX_SPREAD_MIN_SPREAD_CLOSE_PCT` | Порог закрытия, в процентах |
| `CEX_SPREAD_REDIS_ENABLED` | Публикация сигналов в Redis |
| `CEX_SPREAD_DRY_RUN` | Отключение отправки парсером в Telegram и Redis |
| `CEX_SPREAD_TRADER_DRY_RUN` | Симуляция исполнения вместо настоящих ордеров |
| `CEX_SPREAD_TRADER_POSITION_PCT` | Доля баланса для расчёта размера позиции |

Для симуляции связки парсер → трейдер оставьте `CEX_SPREAD_DRY_RUN=false` и `CEX_SPREAD_TRADER_DRY_RUN=true`. Dry-run использует внешние рыночные данные и Redis; это не полностью автономная демонстрация. Для dry-run и реальной торговли используйте раздельные Redis DB, чтобы не смешивать состояние позиций.

## Структура

```text
app/cex/                 Рыночные адаптеры, реестр и анализ спредов
app/cex_spread/          Парсер и Telegram-форматирование
app/cex_spread_trader/   Торговый сервис, состояние позиций, dry-run и адаптеры
app/signals/            Передача событий через Redis
app/config/             Исходная конфигурация проекта
app/core/               Общие модели и статистика
app/telegram/           Telegram API
app/trader/             Общие утилиты и зависимости MEXC-адаптера
app/data/               Рабочие данные, исключены из публикации
```

## Безопасность публикации

Настоящие `.env`, ключи, пароли, серверные архивы, браузерные сессии и история Git в этот срез не включены. Публичный пример содержит только пустые поля секретов.

Перед собственной публикацией можно выполнить локальную проверку:

```bash
python scripts/check_public_release.py
```

Скрипт не проверяет работоспособность и не является полной гарантией отсутствия любого формата секрета. Правила обращения с конфиденциальными данными — в [SECURITY.md](SECURITY.md).
